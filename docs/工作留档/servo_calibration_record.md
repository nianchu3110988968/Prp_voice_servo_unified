## 3. 首次 home 路径核对

当前 `start servo debug <name>` 的真实顺序是：先让全部通道 `FULL OFF`，给选中通道缓存当前 `home` 脉宽，再只开启选中通道。当前 `home=90°`，按源码换算约为 `1500µs`。这一开启过程没有从舵机实际位置到 home 的插值，因为 SG90 不反馈实际轴角。

`home±5°` 只限制首次开启后的串口请求，不能降低首次追到 home 的跳动风险。若首次路径已确认安全，方向识别优先用 `90→92→90→88→90`；首次测试不使用腿部 `70/110`、尾部 `60/120`，也不运行 `happy/shy/curious`。

## 5. 后续测试顺序与停止条件

1. **单路小幅验证**：先尾部，再逐路测试四腿；每次只启用一个通道，先 home，再做 ±2°，确认方向后才考虑 ±5°。
2. **逐路校准**：确定每路可承受的 home 和带余量安全范围；必要时修改 `main/robot_config.h::SERVO_LIMITS`，经构建和明确烧录安排后再复验。
3. **简单动作**：只用已经校准的单路或低风险两路动作验证插值、供电压降和音频共存；旧 `happy/shy/curious` 不作为校准工具。
4. **组合姿态**：先站立基准，再坐下、起身；每个关键帧都必须落在逐路安全范围内，并验证失去PWM保持时机身不会跌落。
5. **步态与语音联动**：组合姿态稳定后才设计对角相位和语音起播动作。四个单关节腿的摆动不保证产生真实前进，必须实测位移、打滑和重心变化。

任一步出现以下情况立即停止本次动作，不再发送下一条：首次跳向不明、碰壳/顶死、持续尖叫或抖动、舵机/线束明显发热、V+明显跌落或极性异常、ESP32复位/串口中断、扬声器失声、PCA/I2C错误、异味或冒烟。优先执行软件结束命令；若舵机仍异常或软件无响应，立即人工断开舵机外部电源。停止后保留最后一条指令、串口日志和测量值，不用重复动作确认故障。

## 6. 下一次最小现场测试

目标仅为确认测试时版本未变、断电音频基线、尾部首次 home 和 ±2°方向；预计独占串口约10～15分钟。当前板上已确认是 `2026-09-28-servo-map-v1`，该最小测试无需重新构建或烧录；若测试时版本已变则停止并与A窗口协调，不在未知固件上发送动作。

现场顺序：重新枚举串口并读版本 → 外部舵机电源断开时确认 `FULL OFF` 和本地音频 → 完成上电前测量 → 接通已核对的单路供电但保持 `FULL OFF`，再次做音频对照 → 人工确认尾部到90°路径 → 仅启用 tail → `92→90→88→90`逐条观察 → 结束单路并切断外部舵机电源 → 再做音频对照。
