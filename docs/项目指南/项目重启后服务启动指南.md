# 项目重启后服务启动指南

本文用于电脑重启后恢复完整语音交互服务。正常情况下不需要重新编译或烧录 ESP32，只需要连接正确的网络并启动电脑端服务。

> 只整理/训练manbo声音时，不需要开启下方整套机器人服务。训练唯一入口是 `E:\Projects2026\Prp_voice_servo_unified\server\tools\start_manbo_training.ps1`，运行后在自己的外部浏览器打开9874；校对9871按需开启，不要同时打开多个校对标签。数据唯一目录是 `E:\Projects2026\Prp_voice_servo_unified\voice_data\manbo`。9872为试听、9873为人声分离，都不需要常驻。2026-09-15旧manbo数据/权重已回收，不能使用历史路径。

完整链路需要三个电脑端服务：

```text
Ollama（11434，大模型）
GPT-SoVITS（9880，个性化语音；启动后选择 GPT + SoVITS 权重）
AI bridge（8000，ASR、对话和 TTS 总入口）
```

启动顺序固定为：

```text
Ollama -> GPT-SoVITS API -> 选择音色模型 -> 使用匹配的参考音频启动 AI bridge
```

“音色模型”不是单个文件，而是一组必须配套保存的配置：

```text
GPT 权重（.ckpt）+ SoVITS 权重（.pth）+ 参考音频（.wav）+ 参考音频原文
```

后续增加多个模型时，必须按这四项组成的“音色档案”选择，不能只替换其中一个权重，也不要按文件修改时间自动猜测模型。

以下命令中的项目路径是：

```text
E:\Projects2026\Prp_voice_servo_unified
```

下划线前不需要添加反斜杠。

## 一、先连接测试网络

先让电脑连接 ESP32 使用的同一个 Wi-Fi 或手机热点，再执行：

```powershell
Get-NetIPConfiguration | Where-Object {
  $_.NetAdapter.Status -eq 'Up' -and $_.IPv4Address
} | Select-Object InterfaceAlias,IPv4Address
```

当前固件配置的电脑地址是：

```text
192.168.43.33
```

对应配置位于 `main/network_config.h`：

```cpp
#define AI_SERVER_URL "http://192.168.43.33:8000/voice/interact"
```

如果电脑的 WLAN 地址不是 `192.168.43.33`，ESP32 将无法访问服务。优先重新连接原来的热点；如果地址长期改变，需要修改 `AI_SERVER_URL`、重新编译，并在用户明确确认后才能烧录。

## 二、启动 Ollama

先检查 Ollama 是否已自动启动：

```powershell
Test-NetConnection 127.0.0.1 -Port 11434
```

如果 `TcpTestSucceeded` 为 `True`，不要重复启动，直接进入下一步。

如果为 `False`，打开第一个 PowerShell 窗口并执行：

```powershell
& "$env:LOCALAPPDATA\Programs\Ollama\ollama.exe" serve
```

看到以下内容表示服务已启动，这个窗口需要保持开启：

```text
Listening on 127.0.0.1:11434
```

模型已安装时不需要每次重新下载。可以用下面的命令确认：

```powershell
Invoke-RestMethod http://127.0.0.1:11434/api/tags |
  Select-Object -ExpandProperty models |
  Select-Object name
```

预期包含：

```text
qwen2.5:3b
```

## 三、启动 GPT-SoVITS 并选择音色模型

打开第二个 PowerShell 窗口，执行：

```powershell
cd E:\Projects2026\Prp_voice_servo_unified

powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\server\tools\start_gpt_sovits_api.ps1
```

首次加载模型可能需要一段时间。保持这个窗口开启，再在其他窗口检查：

```powershell
Test-NetConnection 127.0.0.1 -Port 9880
```

预期：

```text
TcpTestSucceeded : True
```

`start_gpt_sovits_api.ps1` 只负责启动 9880。当前 YAML 的默认权重仍是官方 v2ProPlus 底模；如果要使用训练后的模型，必须在 9880 启动成功后执行下一节的选择命令。

### 3.1 当前可选音色档案

| 档案名 | GPT 权重 | SoVITS 权重 | 参考音频 | 状态 |
|---|---|---|---|---|
| `default_zeroshot` | 官方 `s1v3.ckpt` | 官方 `s2Gv2ProPlus.pth` | `server\voice_models\reference_short_20260907.wav` | 当前启动脚本的默认档案，已完成零样本链路联调 |
| `New_ManBoo` | `New_ManBoo-e5.ckpt` | `New_ManBoo_e4_s80.pth` | `voice_data\manbo\clips\011.wav` | 2026-09-15 最新训练候选；文件已生成，尚需试听验收 |

`New_ManBoo_e2_s40.pth` 是同一实验的较早 SoVITS 检查点，只用于后续 A/B 对比；默认优先试听较新的 `e4_s80`，不能因为文件名较新就省略实际试听。

### 3.2 现在已经启动全部服务：立即切换到 New_ManBoo

先在任意新的 PowerShell 窗口执行以下命令。该操作会热切换正在运行的 9880，不需要重启 Ollama，也不需要烧录 ESP32：

```powershell
$gpt = [uri]::EscapeDataString(
  'E:\AI\GPTSoVITS\GPT-SoVITS-v2pro-20250604\GPT_weights_v2ProPlus\New_ManBoo-e5.ckpt'
)
$sovits = [uri]::EscapeDataString(
  'E:\AI\GPTSoVITS\GPT-SoVITS-v2pro-20250604\SoVITS_weights_v2ProPlus\New_ManBoo_e4_s80.pth'
)

Invoke-RestMethod "http://127.0.0.1:9880/set_gpt_weights?weights_path=$gpt"
Invoke-RestMethod "http://127.0.0.1:9880/set_sovits_weights?weights_path=$sovits"
```

两条命令都应返回：

```text
message
-------
success
```

然后到当前运行 AI bridge 的窗口按 `Ctrl+C`，只停止 8000。`New_ManBoo` 应使用同一说话人的参考片段，不能继续使用默认档案中的旧参考音频。在该窗口执行：

```powershell
cd E:\Projects2026\Prp_voice_servo_unified\server

$env:PRP_TTS_BACKEND = 'gpt_sovits'
$env:PRP_GPT_SOVITS_URL = 'http://127.0.0.1:9880/tts'
$env:PRP_GPT_SOVITS_REFERENCE_WAV = 'E:\Projects2026\Prp_voice_servo_unified\voice_data\manbo\clips\011.wav'
$env:PRP_GPT_SOVITS_PROMPT_TEXT = '然后,点击开始创作,选择一个自己喜欢的背景颜色,这里主播选择的是黑色。'
$env:PRP_GPT_SOVITS_PROMPT_LANGUAGE = 'zh'
$env:PRP_GPT_SOVITS_TEXT_LANGUAGE = 'zh'
$env:PRP_TTS_FALLBACK_TO_SAPI = 'true'

python -m uvicorn ai_bridge_server:app --host 0.0.0.0 --port 8000
```

上面不是“无配置直接启动 uvicorn”，而是在同一窗口先明确设置了 New_ManBoo 的完整参考配置。不要再执行 `start_ai_bridge_gpt_sovits.ps1` 覆盖这些变量；该脚本目前固定使用 `default_zeroshot` 的参考音频。

### 3.3 以后每次重启时选择模型

- 选择 `default_zeroshot`：启动 9880 后不执行热切换，直接使用第四节的 `start_ai_bridge_gpt_sovits.ps1`。
- 选择 `New_ManBoo`：启动 9880 后执行 3.2 的两条热切换请求，再用 3.2 的 New_ManBoo 环境变量启动 8000。
- 新增其他模型：先在上表增加一行，记录配套的 `.ckpt`、`.pth`、参考 WAV 和逐字一致的参考原文，再照 3.2 替换四项路径/内容。不要把不同实验或不同 GPT-SoVITS 版本的权重混用。

热切换只对当前 9880 进程有效；9880 重启后会重新读取 YAML 中的官方默认权重，因此每次启动都要重新选择。这样保留一个安全默认值，同时允许多个模型明确切换。

## 四、启动 AI bridge（default_zeroshot 档案）

打开第三个 PowerShell 窗口，执行：

```powershell
cd E:\Projects2026\Prp_voice_servo_unified

powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\server\tools\start_ai_bridge_gpt_sovits.ps1
```

该脚本会为当前进程配置 `gpt_sovits` TTS，并启动 8000 端口。预期看到：

```text
[ai_bridge] model warm-up: asr={'status': 'ok', ...}, llm={'status': 'ok', ...}
Uvicorn running on http://0.0.0.0:8000
```

三个服务必须按上述顺序启动。不要先手动运行普通的：

```powershell
python -m uvicorn ai_bridge_server:app --host 0.0.0.0 --port 8000
```

普通命令不会设置 GPT-SoVITS 环境变量，默认会使用 Windows SAPI。

本节脚本只适用于 `default_zeroshot`。如果第三节选择的是 `New_ManBoo`，应改用 3.2 中带完整环境变量的启动命令，不要再运行本节脚本。

注意：9880 启动成功并不代表 8000 已自动切换音色。AI bridge 只在进程启动时读取 TTS 环境变量，因此必须在 GPT-SoVITS 启动后，用本节的脚本重新启动 8000，并通过 `/config` 确认 `tts_backend=gpt_sovits`。

## 五、启动后的统一检查

在第四个 PowerShell 窗口执行：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health

Invoke-RestMethod http://127.0.0.1:8000/config |
  Select-Object asr_backend,asr_model_name,llm_backend,ollama_model,persona_prompt_name,tts_backend,gpt_sovits_reference_wav_configured
```

预期关键结果：

```text
status                                ok
asr_backend                           faster_whisper
asr_model_name                        small
llm_backend                           ollama
ollama_model                          qwen2.5:3b
persona_prompt_name                   nuonuo_v1
tts_backend                           gpt_sovits
gpt_sovits_reference_wav_configured  True
```

分别测试文字回复和个性化音色：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8000/debug/dialogue?text=你好糯糯'

$tts = Invoke-RestMethod 'http://127.0.0.1:8000/debug/tts?text=你好呀，我是糯糯'
$tts
Start-Process "http://127.0.0.1:8000$($tts.audio_url)"
```

个性化语音必须返回：

```text
status  : ok
backend : gpt_sovits
```

如果返回 `gpt_sovits_fallback_windows_sapi`，链路虽然仍能发声，但实际使用的是 Windows SAPI，应查看 GPT-SoVITS 窗口中的错误。

`/config` 目前只能确认 GPT-SoVITS 后端和参考音频已配置，不能显示 9880 内部正在使用的权重文件名。因此切换模型时必须保留两条 `message: success` 的输出，并用固定测试句实际试听，不能只凭 `/config` 判断 New_ManBoo 已生效。

## 七、常见故障

### 11434 连接被拒绝

原因：Ollama 未启动。执行第二节的 `ollama.exe serve`。

### 9880 连接失败

原因：GPT-SoVITS 未启动、尚未加载完成或启动窗口已经关闭。重新执行第三节的脚本并查看错误。

### 切换权重返回错误或声音不像目标模型

依次确认：

1. GPT 与 SoVITS 两条切换请求都返回 `message: success`，不能只成功一条。
2. `.ckpt` 与 `.pth` 来自同一实验、同一版本；`New_ManBoo` 使用 e5 + e4/s80。
3. AI bridge 使用该音色对应的参考 WAV 和逐字一致的参考原文；换了权重但沿用其他说话人的参考音频会影响结果。
4. 9880 重启后重新执行模型选择；热切换不会写回 YAML。
5. 用 `/debug/tts` 生成固定句试听。`status=ok/backend=gpt_sovits` 只证明生成成功，音色质量仍需人工判断。

### 8000 报 `WinError 10048`

原因：已有 AI bridge 占用 8000。不要重复启动。检查：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8000
```

如果旧服务是普通 SAPI 模式，需要在它所在的窗口按 `Ctrl+C`，再执行第四节的 GPT-SoVITS AI bridge 脚本。

### 本机接口正常，但 ESP32 收不到回复

依次检查：

1. 电脑 WLAN IPv4 是否仍为 `192.168.43.33`。
2. ESP32 的 `status ai bridge` 是否显示 Wi-Fi connected、ready 为 1。
3. Windows 防火墙是否允许同一局域网访问 TCP 8000。
4. AI bridge 窗口是否出现来自 ESP32 地址的 `POST /voice/interact 200 OK`。

如果需要为当前热点网段放行端口，请使用管理员 PowerShell：

```powershell
New-NetFirewallRule `
  -DisplayName "PRP AI Bridge TCP 8000" `
  -Direction Inbound `
  -Protocol TCP `
  -LocalPort 8000 `
  -Action Allow `
  -Profile Public `
  -RemoteAddress 192.168.43.0/24
```

## 八、关闭服务

在对应的三个服务窗口分别按 `Ctrl+C`，依次关闭 AI bridge、GPT-SoVITS 和手动启动的 Ollama。关闭电脑端服务不会修改 ESP32 固件。
