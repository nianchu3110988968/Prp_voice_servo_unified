# 对话动作选择与语音起播

源码：`2026-09-29-phrase-motion-v1`。9月29日用户在VS Code完成离线回归、固件编译及音频/舵机主机测试，均通过；未烧录、未真实模型或硬件验收。详细证据以`../工作留档/task_progress.md`为准。舵机实测仍暂停，不能因为软件有动作ID就直接给未校准的整机上电。

## 哪个模型在什么时候选动作

- 普通聊天：ASR识别 → Ollama同一次调用生成回复文字和motion → TTS → ESP下载并校验WAV → 播放准备完成 → 起播回调投递动作，同时进入I2S写入。
- 词库命中：ASR识别 → Ollama同一次调用匹配独立词条并为固定回复选择motion → 服务器以Excel固定回复/固定动作优先 → ESP先下载播放预制音频；服务器照常真实TTS，ESP后台下载新音频后丢弃。
- 项目默认对话模型为`qwen2.5:3b`，可由启动环境覆盖；GPT-SoVITS曼波权重只合成声音，不选择动作。每行A→B独立，不维护剧情顺序，不限制你下一句说什么。
- 模型返回的动作只经过允许列表/禁用项校验；旧关键词不再覆盖模型动作。规则后端、模型失败、空输入或无效动作退为`none`，不由隐藏关键词另选一个动作。回复风格、ASR和录音端点不在本次调整范围内。

## 你维护哪三处

| 维护入口 | 修改什么 | 何时生效 |
| --- | --- | --- |
| `server/prompts/motion_selection.txt` | 用中文写“什么情况选什么动作” | 新版服务代码加载后，保存文件，下一次请求读取；不需重新合成缓存 |
| `server/configs/motion_catalog.json` | 每个ID的description及enabled；禁用用JSON的false | 下一次请求读取，固定动作也受禁用开关约束 |
| Excel第一张表的可选“动作”列 | 为这一组A→B指定动作，或留空/填自动 | 保存Excel后按词库指南重新发布预制音频 |

动作提示词控制选择逻辑，不改变回复正文；例如想让认怂时不动，可把对应规则写为“认怂时选择none”。不要在动作文件中修改曼波人格，或要求输出舵机角度。

动作ID固定为以下五项，不能仅在JSON里新增`walk`等ID就得到新动作：

| Excel中文/英文 | 含义与当前固件 |
| --- | --- |
| 自动 / auto / 留空 | 使用模型选择；模型无有效结果时不动作 |
| 不动作 / none | 不发起新动作，不等于切断舵机电源或中断已经执行的动作 |
| 开心 / happy | 复用现有开心摆动并回中 |
| 害羞 / shy | 复用现有收拢姿态并回中 |
| 安慰 / comfort | 当前与curious共用机械动作，尚无独立安慰序列 |
| 好奇 / curious | 复用现有好奇姿态并回中 |

空“动作”单元格不影响原两列表格；错误拼写会在词库读取/发布时报错，不偷偷换成其他动作。同样输入不能对应不同回复或动作；相同回复可有不同动作，并复用一份预制音频。

配置读取失败时，语音仍可继续，但动作只允许`none`，并输出一次对应配置错误；修复配置后下一请求恢复。不需要为了改规则重复启动Ollama或GPT-SoVITS。

## 起播同步与安全边界

- 新的BSP播放入口由统一占用门控制，欢迎音、普通回复、缓存回复使用同一个门；已被占用就失败，不排在其他音频之后。
- 只有音频下载/格式检查成功、获得播放权、I2S可用且完成必要的功放时钟准备后，才执行起播回调；同一回调记录原“播放开始”时间点并尝试投递动作。动作投递本身不做阻塞I2C写入。
- 普通回复、缓存首播和缓存失败后的前台补播都有回调；后台下载丢弃没有回调。开始播放后即使I2S写入失败，也不自动重播或重复动作；播放失败之前尚未起播才允许原有补播分支。
- 机器控制默认关闭、仅尾部调试、动作正在执行/排队或I2C锁忙时，不启动新的语音动作；语音继续。接受的动作若到首个舵机写入前已超过40ms，也丢弃，不迟到执行。此40ms是软件过期保护，不是声学/机械同步精度承诺。
- 原15/11/7/3/0通道、角度限制、FULL OFF及stop/start代次失效保持；未扩大机械动作幅度。接电、校准和实测仍按单独舵机指南，不因该功能自动启用五路。
- 物理出声与舵机位移仍受DMA、任务调度、50Hz PWM和机械响应影响，必须后续实测；软件起播事件不等于零时差。旧音频尾部DMA排空、空闲数字静音和功放准备时间保留。

在VS Code空闲PowerShell运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 'E:\Projects2026\Prp_voice_servo_unified\tools\verify_servo_channels.ps1'
```

包含词库/模型动作离线测试、原日志回归、`platformio run`、生产下载/起播门的主机测试、PCA9685和动作任务主机测试。不调用真实模型、不重启服务、不烧录、不驱动硬件；出现模拟404/超时等日志不代表真实服务失败，最终须看到PASS。

测试会主动制造HTTP404、超时、空/超限音频、无效WAV、播放占用和I2S写入失败，用来确认这些情况下不误播、不重复动作。`fake_error`及相关失败提示属于这些模拟用例，最终全套PASS才是验收依据。stdout/stderr分流可能使错误提示显示在局部PASS之后；不要单凭出现“失败”二字判断测试结果，也不要把Compiling/Generating等输出粘回PowerShell执行。

固件构建固定使用用户目录下的`.platformio/penv/Scripts/python.exe -m platformio`，输出会显示实际Python路径和Core版本，避免PATH上的旧Core混入。专用环境不存在或启动失败时脚本停止，不自动回落旧Core或重装工具。运行期间不要同时在其他终端或VS Code任务里构建/更新PlatformIO；已有语音服务无需停止。

验证通过后，服务端代码需在原可见终端/启动器停止旧实例后重新加载一次；固件需用户另行确认烧录才能使用新起播点。已在运行的服务不会自动因源码保存更新。先保留舵机断电测试语音和词库，待万用表、供电检查与校准完成再测动作。真实语义命中率和动作/声音同步偏差不由主机测试证明。

核心实现：`motion_policy.py`维护模型可见规则及允许ID；`phrase_library.py`读取可选动作、独立匹配和缓存复用；`dialogue_service.py`生成文本/动作；`audio_reply_player.cc`下载校验和一次起播回调；`bsp_board.cc`/`audio_playback_gate.h`统一播放权与起播位置；`robot_motions.cc::tryStartVoiceMotion`执行非阻塞准入和过期拒绝。
