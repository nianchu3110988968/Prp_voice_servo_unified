保存间隔单位是“轮”，不是分钟。GPT 设置每 5 轮保存，就要跑完第 5 轮才有这一档导出的试听模型；中途强行停止不能保证留下可用模型。如果非常需要 GPT 的中间试听点，可改成每 1 轮保存，但会增加磁盘写入和导出文件数量。

### 2.2 要多久

**今晚快速版先按约 10～30 分钟预留训练时间，另留几分钟加载和试听；这是粗略安排，不是本机测量结果，也不保证 30 分钟内完成。** 本机还没有这套语料的训练首轮耗时，不能给出准确倒计时。

影响时间的不只是素材长度，还包括 GPU 功耗/温度、其它程序显存占用、Windows 数据加载、批大小和保存速度。接通笔记本电源，避免睡眠。

本安装的两个数据加载器会对不足 100 条的小集合重复采样。若 39 条都通过过滤，当前逻辑会重复为 78 个训练条目，然后还可能按长度分桶、补齐批次。因此不能简单拿“39 ÷ 4”当作每轮实际步数，更不能把重复后的 78 条写成 78 条独立录音。

更可靠的估时办法：

1. 分别记录 SoVITS、GPT 开始时间和前两轮结束时间。
2. 第一轮常含模型加载与缓存建立，第二轮更接近稳定速度。
3. `剩余时间 ≈ 剩余轮数 × 最近一轮耗时 + 后续保存时间`。两种模型必须分别估算。
4. 例：SoVITS 第二轮实测 50 秒，剩 2 轮，则纯训练约剩 100 秒，再加保存时间；这只是计算示例，不是本机结果。

原先建议的 SoVITS 8 轮 / GPT 15 轮可以留作后续比较。短版不够像，不代表路线失败；训练更多也不保证更好。只有 3 分钟、题材集中的教程旁白，可能学到旁白语气，但对陪伴式台词和多种情绪的覆盖有限。

如果只想立刻听声音方向，也可用官方底模加这批旁白的一段 3～10 秒参考音频做零样本试听；那不是这次微调后的效果，两者要分开标注。

## 3. 内部究竟做了什么

可以把它理解成“整理教材 → 制作机器能读的教材 → 微调两个互相配合的模型 → 给新句子配音”。

```text
原始视频/音频
  → 切成短音频 + ASR 生成文字 + 人工逐句校对
  → 一键三连：文本音素/BERT、语音特征、语义 token（Pro 还提取说话人特征）
  → SoVITS 微调：学习如何把语音表示还原成这一类声音
  → GPT 微调：学习从文本条件预测语音语义 token
  → 推理：新文字 + 参考音频/参考文本 + 两个模型 → 新 WAV
  → 通过 API 和 AI bridge 接入机器人（本次新音色尚未执行）
```

| 名词 | 通俗解释 | 本项目里做什么 |
| --- | --- | --- |
| 预训练底模 | 已经学过大量语音的基础模型 | 不是从零教机器说话，而是在它的能力上适应目标音色 |
| 微调 | 用自己的数据继续小幅更新参数 | 形成这次实验的专用权重 |
| ASR / Whisper large-v3 | 听声音写文字 | 帮忙做训练标注；不是最终声音，也不是本项目对话 ASR 必须更换的模型 |
| 音素 | 比汉字更接近发音的单位 | 告诉模型该怎么读字 |
| BERT 特征 | 对文本上下文的数值表示 | 提供中文文本条件，不是负责聊天的大模型 |
| CNHuBERT / SSL 特征 | 从波形提取的语音表示 | 为后续语义提取和声学训练提供输入 |
| 语义 token | 语音内容/表达的离散编号序列 | 不是人工台词，也不是 Ollama 生成的文字；v2ProPlus 这里使用约 25 Hz 的语义表示 |
| GPT（本软件） | Text-to-Semantic 模型 | 预测语音 token；**不是 Ollama/qwen，不负责糯糯说什么** |
| SoVITS | 将语义、文本和音色条件变成声音的模型 | 负责合成波形；微调不只是一个“改音高滤镜” |
| G / D | 生成器 / 判别器 | G 学生成声音，D 在训练时帮助判断真假；部署不需要把 D 权重填入推理框 |
| batch size | 一次送入多少训练样本 | 越大一般越占显存，不代表效果必然更好 |
| step / epoch | 一次参数更新 / 遍历一次训练采样集合 | 保存通常按 epoch；小集合可能重复采样，不能直接等同于原始音频听一遍 |
| loss | 当前训练目标的误差 | 用来观察异常趋势；数值下降不等于音色一定更像，需要试听未训练句子 |
| checkpoint | 训练存档 | 完整存档用于续训；导出的小模型用于推理，二者用途不同 |

训练学的是发声规律，不是把教程全文录进播放器。推理时你输入从未出现过的新句子，模型应生成新音频；若只能复述训练句，不能算泛化效果好。

## 4. 第 0 页：前置数据集获取工具

本次已做完这一页对应工作。以后换素材时才需要重新走相关步骤，不是每次打开项目都点一遍。

### 0a：UVR5 人声伴奏分离、去混响、去延迟

作用：从有伴奏的素材中尽量提取人声，或减轻混响。按钮打开独立处理界面；输入/输出目录指定素材及结果位置，分离模型决定处理方式，输出格式决定文件类型。

有明显音乐才考虑分离，干净单人旁白可跳过。分离不是无损修复，可能留下金属音、失真或漏字；必须听处理后的文件再决定是否训练，不要把背景音乐一起当作目标声音。

### 0b：语音切分工具

作用：把长音频按静音附近切成短段，方便逐句标注、训练和排查坏样本。本安装输出 32 kHz WAV，不改原视频。

| 页面字段 | 意义 | 本次/起步值 |
| --- | --- | --- |
| 音频自动切分输入路径 | 一个音频文件或目录 | 填真实绝对路径，不用界面示例的 D 盘路径 |
| 切分后的子音频输出根目录 | 新 WAV 放在哪里 | 每批素材单独目录，避免和旧批次混用 |
| threshold | 低于该音量的部分作为静音候选；单位 dB | -34；值越接近 0，越容易把较轻的声音也当静音 |
| min_length | 分段的最短长度规则，短段倾向与后段连接 | 4000 ms；不是保证所有输出严格 ≥4 秒 |
| min_interval | 可切分的最短静音区间 | 300 ms；不是每 300 ms 强切一刀 |
| hop_size | 检测音量曲线的时间步长 | 10 ms；更小计算更多，不一定更好 |
| max_sil_kept | 切分时保留静音的长度控制 | 500 ms；防止首尾拖太久 |
| max | 归一化分支的目标峰值 | 0.9，不是语速或训练强度 |
| alpha_mix | 归一化信号混入比例 | 0.25，即 25% 归一化信号 + 75% 原信号；不是最终峰值一定为 0.9 |
| 切割使用的进程数 | 分配输入文件的 CPU 工作进程数 | 4；不是显卡数量，单个长文件不一定因此快 4 倍 |
| 开启语音切分 / 输出信息 | 启动处理 / 查看进程结果 | 完成后检查文件并试听首尾有无截字 |

本次切片目录有 40 个文件，但正式 `.list` 只引用前 39 个。保留末尾日语原文件不等于把它加入训练，不需要为此删除原素材。

### 0c：语音识别工具

作用：为切片生成标注草稿，不是训练音色。

| 字段 | 含义与操作 |
| --- | --- |
| 输入文件夹路径 | 切好的音频目录 |
| 输出文件夹路径 | 自动识别的标注文件放置位置；重识别时用新目录，避免覆盖人工校对稿 |

### 0d：语音文本校对标注工具

> 当前版本有多窗口串页缺陷：所有浏览器共享当前页码，一个窗口翻页/刷新会改变另一个窗口提交的目标位置。**只保留一个校对窗口操作，不要同时打开内置浏览器与Chrome的校对页。** Submit Text前确认当前Text编号与音频、文字匹配；恢复期间使用9873，旧9871页面不要提交。

主页面填写 `.list` 的完整路径，点击开启标注 WebUI；本机编辑界面为 `http://127.0.0.1:9871/`。

标注一行的结构：

```text
音频绝对路径|说话人标签|语言|音频真正说出的文字
```

说话人标签是数据标识，不必强行改成实验名；当前 `mambo_tutorial_narrator` 可以配合实验 `manbo_narrator_zh_v1` 使用。文字必须忠实于录音，不能为了通顺改成录音里没说的句子。

**最重要的操作顺序：试听当前批 → 修改文字 → 点击 Submit Text → 确认提交 → 再翻页。全部批次提交后再 Save File。**

- `Submit Text` 才把当前批文本框内容提交并写入文件。
- `Save File` 保存的是已提交的内存内容，不能替代当前批的 Submit Text。
- 未提交就翻页/刷新可能丢失修改。仅文件修改时间变了，也不能证明你改的句子已保存。
- 确认保存应直接重读 `.list` 中的具体句子，并核对条目数。

校对子页面的英文控件：

| 控件 | 用途与注意事项 |
| --- | --- |
| Text / Output Audio | 当前条目的文本和音频播放；边听边核对，不要只读自动稿 |
| Index / Change Index | 设置起始条目索引并跳转，编号从 0 开始；先提交本批文字再跳 |
| Previous Index / Next Index | 上一批 / 下一批；翻页不会自动收集未提交的文本框修改 |
| Batch Size | 一屏显示多少条，本安装这里不可编辑；与训练 batch_size 无关 |
| Submit Text | 提交当前批文字；无需先勾选每条的 Yes |
| Save File | 把已提交的内容保存到清单，不替代 Submit Text |
| Yes / Choose Audio | 选中该条，用于删除、合并、拆分操作；不是“此句校对完成”的标记 |
| Invert Selection | 反选当前条目的选择框 |
| Delete Audio | 本源码从标注列表移除选中条目并保存，不删除对应 WAV；索引会变化，后续训练不再引用该条 |
| Merge Audio | 合并选中多段并拼接已提交文本，**会覆盖第一段 WAV**，同时修改清单；不是只在播放器临时拼接 |
| Interval | 合并音频之间插入的静音秒数，不是翻页间隔或训练参数 |
| Audio Split Point(s) / Split Audio | 选中单条，按秒指定切点；**会把原 WAV 改成前半段**并写出后半段新文件，随后必须重分配两段文字 |
| Light Theme / Dark Theme | 切换明暗主题；先提交文字，避免页面重载丢失未提交编辑 |

**本次切片已准备好，不需要点 Merge Audio 或 Split Audio。** 这两个操作会改动音频，使用前必须备份相应素材和清单；只为导出连续音频/整段正文，不应在这里合并训练条目。任何删改条目都会影响编号，不能沿用旧页码定位。

本项目曾因“页面修改未提交”误导出旧稿，已经留档。正式文件不能与带 `INVALID_pre_submit` 的旧错误文本混用。

## 8. 今晚如何判断效果，不只听一句“像不像”

固定同一段参考音频、同一份参考文本、同一套采样参数，分别生成以下未训练句子：

1. “你好，我是糯糯，今天也很高兴见到你。”
2. “你可以慢慢说，我会认真听着。”
3. “今天已经做了不少事情，先休息一小会儿吧。”
4. “现在是晚上十点半，明天还有两件事情要做。”
5. “嗯？你想再试一次吗？”

分别听：音色相似度、漏字/重复、中文发音、金属音/底噪、停顿和语气。生成音频用“实验名 + GPT轮数 + SoVITS轮数 + 句子编号”保存，并记录生成用时。相同条件重复生成可观察稳定性，不用单次偶然结果判断最优模型。

优先比较官方底模+旁白参考（零样本）、SoVITS e2/GPT e5、SoVITS e4/GPT e5。早一点保存的模型也可能更自然。若音色较像但语气像教程，是素材风格影响；改糯糯人设能影响回复文字，却不能保证把教程配音变成温柔声线。

公开展示或发布模型前应确认素材及声音使用授权，并清楚标明是合成语音，不冒充原说话人。

## 9. 常见问题、停止与续训

- **CUDA out of memory**：先停止失败任务并确认退出，检查其它显存占用，再降低 batch；不要同时再开一个训练进程。
- **底模/路径找不到**：核对 v2ProPlus、完整实验名和实际目录。教程中的示例路径不是本机素材。
- **页面显示完成却没有权重**：查看 traceback、目标轮数、保存间隔和“导出小模型”勾选；本 WebUI 的完成提示不能替代文件检查。
- **只有 SoVITS 权重**：只完成了一半，不等于成对微调已完成。
- **日志有 warning**：warning 不等于失败。本次格式化中 TypedStorage / ComplexHalf 是库警告；语义提取使用 `strict=False` 加载底模，打印的额外 `sv_emb/ge_to512/prelu` 键不能单独证明失败，本次还核对了全部 39 条语义产物。其它阶段出现 missing keys、traceback 仍须单独判断，不能一概忽略。
- **想停下来明天继续**：先等保存点完成，核对 logs 中续训存档。点终止不会自动补存，未保存的更新会丢失。
- **重新点训练是否从零开始**：本安装会尝试从对应实验目录的训练 checkpoint 恢复。保留相同实验名、版本和数据，核对日志中起始 epoch/ckpt_path；不要假定它一定重新从底模跑。
- **想从 4 轮练到 8 轮**：总轮数通常设目标 8，不是再填 4；GPT 类似。恢复的具体起始轮、优化器状态要看日志。只保留导出小模型不等于完整续训存档齐全。
- **换素材或做独立对照实验**：用新的实验名并重新格式化，避免旧 checkpoint 被自动续用；保留旧文件，不盲删缓存。

## 10. 试听之后如何接入机器人、切换多个音色

网页试听成功不等于机器人已切换。接入必须绑定四项：**GPT 权重 + SoVITS 权重 + 该音色参考 WAV + 精确参考文本/语言**。

目前已有：GPT-SoVITS API 接入、手动权重热切换、YAML 默认权重配置。**项目级“选一个名字就同时切换整套配置”的模型注册表和脚本尚未实现。** 多个实验权重可以保存，不用覆盖旧模型。

接入时按以下顺序另行操作：

1. 保存试听 WAV 和模型组合，确认这套声音值得接入。
2. 关闭 9872 推理服务以释放显存，再为 9880 API 配置这对权重。
3. 在 AI bridge 启动配置中换成旁白参考音频和对应文本；只换权重但保留本人旧参考音频，声音仍可能受旧参考影响。
4. 启动 Ollama 11434、GPT-SoVITS 9880、个性化音色配置的 AI bridge 8000。
5. 检查 `/config` 和 `/debug/tts`，确认 `backend=gpt_sovits`，不是 SAPI 回退，然后才通过 ESP32 试听。

准确的 API 切换命令和重启命令见 [自定义音色训练与接入说明](custom_voice_training_and_tts_integration.md) 第 9 节，以及 [项目重启后服务启动指南](项目重启后服务启动指南.md)。切换音色本身不需要烧录 ESP32。本次仅编写教程、核对数据，没有修改服务配置、训练权重或板上固件。
