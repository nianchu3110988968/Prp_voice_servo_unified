# ESP32 播放音量接口（prp-volume-v1）

2026-10-12，C 音量窗口负责固件与本协议；D UI 窗口负责 desktop_ui/、串口客户端和用户状态。接口已冻结供接入，软件测试/构建已有通过证据，板端验收尚未执行，不能显示为已交付功能。固件目标版本 `2026-10-12-volume-v1`。

## 传输与命令

复用现有唯一串口所有者，115200，ASCII 命令，每次以 LF（或 CRLF）结束。UI 不得与旧控制台、监视器或上传器同时打开串口。不新增服务、不改变 Wi-Fi/TTS/ASR。

```text
volume get ui_001
volume set ui_002 50
volume set ui_003 0
volume set ui_004 100
```

- 请求 ID 必填，1～32 个 ASCII 字母、数字、`_`、`-`；客户端在本次连接内使用不重复 ID。
- `set` 值为十进制整数 0～100（含端点，允许前导零），不接受正负号、小数、百分号、额外参数。不裁剪非法值；拒绝时保持原设置。
- 0 静音；100 保持源 PCM 原幅度；50 为线性振幅减半，不代表主观响度减半。默认和每次重启都是100。没有独立 mute 命令，静音用 set 0；取消静音由 UI 显式恢复它保存的最近非零值，再等待回执。
- 不持久化、不写 Flash，不随拖动连续发送；UI双方已约定显式点击“应用音量”发送一次，一次只保留一个在途请求。
- 单行最长94字节（含CR如有，不含LF）。分次抵达的串口数据拼接到LF再处理；超长行被丢弃至LF，可能只有普通警告，UI按超时未确认处理；不得把被截断的命令前缀当有效请求。

## 设备回执

ESP 日志行（可能带颜色、时间和 TAG）中以 `VOLUME ` 开始的 JSON 是唯一音量回执。示例是协议示例，**不是实测记录**：

```text
VOLUME {"protocol":"prp-volume-v1","id":"ui_002","op":"set","ok":true,"error":"","percent":50,"muted":false,"ready":true,"persistent":false,"firmware":"2026-10-12-volume-v1"}
```

`get` 结构相同，`op` 为 `get`。`percent` 始终是设备当前软件衰减系数；`muted` 等价于 percent==0。`ready` 表示PCM16输出已初始化，不表示网络已连接、正在发声或硬件完好。`ok:true` 的 set 表示系数已写入设备原子状态，由下一 PCM 块读取；它不是电脑请求发送成功或声学实测。

失败为 `ok:false`，`error` 为 `invalid_command`（语法）、`invalid_value`（值非法）或 `not_ready`（播放初始化未完成/失败）；percent保留原值。语法无效时 id 可能为空或截断、op 不可依赖，不应确认任一正常请求。`not_ready` 回执有正确 ID/op/protocol，足以证明协议支持，但 UI 禁用调节，允许后续 get。

字段只在协议版本符合时解释；验证 JSON 类型、ID/op匹配、百分比0～100、muted一致、firmware字段存在。不要解析普通“发送成功”日志作为回执。

## UI 状态与确认规则

| 状态 | 判定与行为 |
| --- | --- |
| 未连接 | 未持有串口，实际值未知，禁用音量 |
| 探测中 | 连接后只发 `volume get <新ID>`，最多等待2秒 |
| 就绪 | 收到匹配 get，protocol正确、ok/ready为true；显示设备percent并启用控件 |
| 不就绪 | 支持协议但not_ready；禁用调节，用户重查或稍后查询 |
| 待确认 | set已发送，分开展示请求值和上次确认值；不提前显示成功 |
| 已确认 | 匹配set、ok/ready为true且percent等于请求值；更新最后确认值 |
| 拒绝 | 匹配失败回执，显示原因与回执中的原值，不宣称设置成功 |
| 超时/未确认 | 2秒内无匹配有效回执；可能设备已设置但回执丢失。保留未知标记，用新ID get核实，不能自动判为未设置或自动重试set |
| 不支持或暂不可用 | 初次get无回执；旧固件不会回应。不区分“旧固件”与断线/忙碌丢包，禁用音量并提示检查版本/重查 |

迟到回执不能确认新请求；断线/重连清空请求与确认态，重新get，不自动回写旧值（设备重启可能已回100）。2秒为UI超时策略，不是实时性保证；已有同步串口命令可能阻塞处理。

## 音频与动作边界

统一PCM16小端入口覆盖欢迎/提示音、动态回复和缓存前台回复。每块最多240采样（16kHz时15ms），只读源音频，不改缓存、不重新TTS，不影响录音。

set不等待音频结束，不抢播放锁；系数原子读写。已缩放的当前块及DMA内音频保留旧系数，正常16kHz排队约一个DMA环90ms加当前块15ms；这不是硬实时上限。播放结束/写入失败仍在原播放权内等待一个DMA环加20ms余量。静音继续送零PCM、维持I2S时钟、执行原起播回调，**静音不停止舵机**，不改变任何动作准入条件。动作停止仍使用原停止功能并以FULL OFF回执为准。

初次初始化和重新启用输出保留20ms功放准备；回调只在播放权和准备成功后、首写之前运行一次。部分写入精确续写剩余字节，零进度/越界写入返回错误，错误不重播已排队前缀。100%在PCM样本层逐字节不变，仍需实听排除分块对实际I2S时序的影响。
