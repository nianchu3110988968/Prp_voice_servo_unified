## 2026-09-29：需求纠正——每行独立输入→固定回复

以用户最新澄清为准：每组对话只定义A1→B1、A2→B2，各组之间没有前后依赖。演示情节和说话顺序由用户自己安排；设备不需要知道下一句是什么。此前的严格顺序剧情方案是agent误解，已经撤销，不能据其实现状态机。

维护仍以“用户示例输入/标准输出”两列为基础，源码已支持可选的“动作”列；不需要本句编号、下一句编号、首句入口、进度、解锁或退出/重开剧情口令。表格行的排列不影响触发。

| 用户示例输入 | 标准输出 | 动作（可选） |
| --- | --- | --- |
| 曼波，开始面试 | 请问贵公司允许员工比老板聪明吗？ | 不动作 |
| 你有什么特长 | 我擅长把简单的事情想得毫无进展。 | 自动 |
| 你被录用了 | 坏了，我只是来蹭空调的。 | 开心 |

无论之前聊了什么，只要本轮命中对应输入，就采用该行固定回复；可以先触发第三行、再触发第一行，也可以重复触发同一行。未命中按普通对话处理，不存在需要保留或推进的剧情位置。匹配依据本轮识别与词条，不按历史对话解锁；本次纠错不擅自修改既有语义匹配算法或ASR行为。

动作可固定或自动选择，并在对应语音起播点尝试启动；后台真实模型/合成/新音频下载丢弃和真实耗时日志要求保留。不为不存在的剧情推进新增播放确认接口，不改请求关联或后台任务管理。起播占用、忙碌时跳过动作等边界见`voice_motion_selection.md`。

上表只是说明，未写入用户Excel。动作列与起播回调已写入源码，尚需以进度记录确认验证/烧录/实测状态。现有两列语义词库与缓存机制仍是实现基础，不要求每段剧情拆工作表或另建多工作表协议。回归覆盖乱序触发、重复触发、中间穿插普通聊天、固定回复不改写、起播动作仅触发一次和真实后台流程；主机测试不证明真实模型命中率。

## 你需要维护什么

维护原文件 `E:\Projects2026\Prp_voice_servo_unified\docs\响应词对话\响应词对话1.xlsx` 的第一张工作表。首个非空行写下面两个表头，一行一条示例；其他工作表不读取。程序只读Excel，绝不替你覆盖或保存正在编辑的内容。

| 用户示例输入 | 标准输出 |
| --- | --- |
| 你好 | 你好呀，我在这里。 |
| 早上好 | 你好呀，我在这里。 |

上表仅说明格式，不是已写入用户文件的内容。相同标准输出会合成一份音频，可对应多个示例。用户可以换一种说法，由Ollama判断是否同一语义意图，不是固定字符串或关键词命中。

- 第一版最多64个示例，示例合计最多16000 UTF-8字节；每条示例最多512字节。
- 标准输出最多240 UTF-8字节（约80个汉字）；建议1～2个短句。超过限制会明确报错，不会静默截断成普通回复的48字。
- 输入和输出必须填写，动作可留空（等于自动）。使用单行文本，不使用公式、合并单元格或单元格内换行。相同输入不能对应不同回复或动作；相同回复但不同动作分别匹配，预制音频只合成一份。
- 可选“动作”（或“反馈动作”）列接受：自动、不动作、开心、害羞、安慰、好奇，以及auto/none/happy/shy/comfort/curious。动作选择规则和禁用方式见`voice_motion_selection.md`；原两列表格不用补列也能使用。
- 别名表头也接受“用户输入/示例输入/触发台词”和“设备标准输出/设备预期的标准输出/预期输出/固定回复”，但每类只能有一列。
- 合成WAV必须为16kHz、单声道、PCM16，非空、非全静音且不超过512KB（约16秒）。过长需缩短标准输出。

## 后续修改词库或换音色

保存Excel后再次运行上述生成脚本即可，无需改固件或重复启动服务。缓存绑定Excel文件SHA256、TTS参数、参考音频内容、当前角色档案、权重配对哈希及音色修订号；表格或配置改变时，旧缓存暂不命中，回正常流程。仅改变Excel格式也会要求重新生成，这是保守失效策略。

预制音频和清单在 `server/phrase_cache/<角色ID>/<角色配置摘要>/`，不提交Git；用内容哈希命名，整批成功才原子替换清单，生成失败保留旧清单及音频（旧清单不匹配新表格时仍不会使用）。历史缓存不会自动清理，避免删除用户试听依据；日后需要清理再单独处理。

使用启动器切换角色后，服务端按角色/音色配置隔离缓存，旧角色URL被拒绝；切回同一配置可复用对应清单。修改音色时在角色档案更新 `phrase_voice_revision`，不再单独维护该环境变量。旧角色尚未开始合成的后台任务会取消，已经下发的音频无法撤回，宜在交互空闲时切换。不要在外部网页/客户端绕过启动器热切换9880，上游没有当前权重查询接口，服务端无法侦测这种修改。历史缓存不自动删除，词库也不会自动批量生成。

更换Excel位置用 `PRP_PHRASE_WORKBOOK` 的绝对路径；关闭词库用 `PRP_PHRASE_LIBRARY_ENABLED=false`。这些环境变量必须在启动AI bridge的同一终端设置后重启才生效，不插入日常启动指南的主线。

## 实际链路与日志

```text
录音 → 上传 → 真实ASR → Ollama语义判断
                         ├─ 未命中/无有效缓存 → 原回复生成 → TTS → 下载 → 播放
                         └─ 命中 → 首包：标准回复、预制音频URL、任务URL
                                   ├─ ESP：下载缓存 → 播放 → 继续聆听
                                   └─ 服务端：标准回复真实TTS → 后台结果
                                              ESP后台取结果 → 下载新音频 → 丢弃，不播放
```

命中时Ollama同一次真实调用执行语义判断并返回白名单词条ID和动作ID；固定动作以Excel为准，自动时采用模型动作。标准回复从Excel取出后原样提交给TTS，不再多调用一次自由回复LLM来生成不用的文字。`dialogue` 包含这次语义判断/动作与固定回复选择的真实耗时。未命中时还会进行原回复生成，耗时包含两者，因此未命中可能比原流程略慢；匹配调用默认最多等待8秒（可配 `PRP_PHRASE_MATCH_TIMEOUT_SECONDS`）。不能承诺所有场景都加速。

录音、ASR、阈值、归一化及字幕幻觉问题没有在此功能中修改。`recognized_text`和“识别”始终是真实ASR结果，不拿示例句冒充识别成功；“回复”才是固定标准输出。语义匹配仍可能误判，需用否定句、相近但不同意图和静音误识别回归，不等于已修复“字幕by索兰娅”。

正常非命中中文日志格式保持原样。命中分支按同一 `X-Request-ID` 关联：

| 字段/日志 | 含义 |
| --- | --- |
| 【词库命中】识别 / 回复 | 真实识别与选定标准回复，各输出一次；不反复刷“预设演示文本” |
| 首包的asr/dialogue | 实际ASR、语义匹配和回复选择耗时 |
| 首包tts/total_pipeline=-1，tts_status=pending | 后台尚未完成，不能显示成0ms或合成成功 |
| 缓存下载开始/结束、缓存播放开始/结束 | 实际预制WAV的GET和I2S播放API边界，仍以本轮开始监听为零点 |
| 录音结束至播放 | 用户等待这次实际缓存播放的时间，不包含事后后台下载 |
| 后台JSON收到 | ESP实际拿到最终后台结果的本地时间点；可能晚于服务端合成完成 |
| 后台timings_ms.tts | 本轮真实合成调用耗时，含等待TTS互斥锁、格式转换、可能的备用音色流程 |
| 后台timings_ms.total_pipeline | ASR开始到本轮真实TTS完成，包含调度/排队间隙 |
| timings_ms.total_request | 命中时为首包字典就绪，不冒充后台总耗时；非命中仍为原整请求边界 |
| 后台timings_ms.background_total | 服务端接到原请求至后台结果就绪；与首包耗时明确区分 |
| 后台（不播放）下载开始/结束 | ESP真实下载新合成WAV，但不调用音频驱动；独立trace副本，不覆盖实际播放时间 |

两端不减绝对时钟。服务器打印的后台耗时与ESP从结果取出的字段一致；缓存生成的历史耗时不当作这次实时TTS耗时。实际播放完成不代表后台也完成，后台失败会另行显示，不伪装成功。GPIO/I2S日志依然不是声学首尾声证据。

ESP为避免影响缓存首播，在缓存播放完成后才启动后台取结果/下载，随后不阻塞续聊。取结果使用最多20秒一次的异步长轮询，避免每半秒刷访问日志；后台下载仍可能与下一轮网络传输共享带宽，需实测。

## 失败与资源边界

- 无库、未命中、匹配失败、缓存缺失/损坏/过期：回原回复/TTS流程。新固件仅在预留了后台名额时发送 `X-Voice-Capabilities: phrase-cache-v1`，旧固件不发送。
- ESP收到命中首包后缓存下载/格式解析失败且尚未开始播放：等待该轮真实TTS并在前台补播；不会再次推理。若已进入播放API后失败，不重复播可能已听过的片段。
- 缓存播放成功：新合成音频只下载不播放。后台任务/下载失败、断网、任务过期会告警，不补播；生成失败的音频不会伪装成已下载。
- ESP最多2个待处理后台任务，服务端最多4个在途任务、保留最多32项结果，完成后保留300秒，原任务超时180秒。超时执行线程无法强杀，仍占用槽位直到真正结束，防止无限积压。网络单次长轮询及下载超时可能使ESP实际退出略晚于180秒。
- 后台下载不额外申请512KB音频缓存；收到的网络字节直接丢弃，仍检查HTTP/空响应/超限。正常播放的512KB上限保留。JSON响应缓冲从2KB改为堆上8KB以容纳扩展字段；截断响应明确失败。
- ASR/回复/历史在一条互斥通道处理；TTS调用互斥，避免同时操作GPT-SoVITS共享状态。同步模型调用移入工作线程，缓存GET和异步任务查询不会被TTS占住事件循环。
- 维护接口仅本机回环地址可用，拒绝浏览器Origin并要求维护头；不接受客户端上传任意Excel路径或模型生成的任意音频URL。现有服务器仍是受信局域网开发服务，不应直接暴露公网。

核心位置：`server/services/phrase_library.py`负责只读Excel/语义ID白名单/缓存发布；`phrase_jobs.py`负责有界任务；`ai_bridge_server.py`负责首包和后台结果；`main/phrase_background.cc`负责取结果/下载丢弃；`main/audio_reply_player.cc`是实际下载与不播放分支。测试不能代替真实语义命中率和硬件听感验收。
