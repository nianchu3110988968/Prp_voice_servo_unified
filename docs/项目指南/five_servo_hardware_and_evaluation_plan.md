## 3. 舵机扭矩与尺寸判断

### 3.1 不能只按“9g 或 5g”选择

舵机重量不是扭矩指标。需要先确定脚部是：

1. **装饰摆动**：脚不承受机器人重量，只带动较轻的毛绒和骨架；
2. **姿态调整**：脚会推动身体改变坐姿或重心；
3. **承重/移动**：脚需要支撑或移动整机。

只有第一种情况适合优先尝试 2g、3.7g 或 5g 微型舵机。后两种情况不能为了缩小体积而直接降低扭矩。

### 3.2 估算公式

舵机轴所需静态扭矩可按下式初估：

```text
静态扭矩（kgf·cm）≈ 负载质量（kg）× 重心到转轴距离（cm）
选型扭矩 ≥ 静态扭矩 × 动态系数 ÷ 传动效率
```

- 缓慢摆动可先取动态系数 `1.5–2.0`。
- 快速启停、毛绒挤压或可能卡住时取 `2.0–3.0`。
- 简单连杆的传动效率可暂按 `0.6–0.8` 估算。
- 正常动作所需扭矩最好不超过舵机堵转扭矩的约 `40%–50%`，避免发热、抖动和寿命快速下降。

示例：若整机 1kg，由四脚平均承重，有效力臂 3cm，动态系数 2，传动效率 0.7，则单腿建议扭矩约为：

```text
(1kg ÷ 4) × 3cm × 2 ÷ 0.7 ≈ 2.1kgf·cm
```

这时普通 SG90 的余量已经不大，更小舵机通常不合适。若单只脚只是带动约 30g 的软质部件、重心距轴 4cm，则设计扭矩约为 `0.4kgf·cm`，才有机会使用更小舵机。

### 3.3 当前建议范围

| 部位/工况 | 建议起始扭矩等级 | 初步选择方向 |
| --- | ---: | --- |
| 不承重的短脚摆动 | ≥0.8–1.2kgf·cm | 3.7g–5g 微型舵机可试 |
| 带动较厚毛绒或调整坐姿 | ≥1.5–2.5kgf·cm | SG90 级或更可靠的同尺寸舵机 |
| 承重或推动整机 | ≥2.5–4kgf·cm，需实测 | 不建议缩小；优先结构减载或金属齿轮舵机 |
| 轻质尾巴摆动 | ≥0.3–0.8kgf·cm | 2g–3.7g 舵机可试 |

不同厂商标注差异很大，上表不能替代样品实测。

### 3.4 最小扭矩实测

在购买五个新舵机前，先制作一个脚部和尾巴样件：

1. 在最不利姿态下，用弹簧秤或电子秤测量使部件刚开始运动的力。
2. 记录施力点到转轴的垂直距离。
3. 用“力（kgf）× 距离（cm）”计算静态扭矩。
4. 乘以至少 2 倍安全系数，并考虑毛绒挤压后的附加阻力。
5. 用一只现有 SG90 做低速限位测试，同时测启动、运动和堵转趋势电流。

需要记录：整机质量、单肢质量、力臂、测得力、计算扭矩、动作角度、动作时间、峰值电流、是否发热或卡滞。

## 4. 单 ESP32-S3 合并控制方案

### 4.1 可行性结论

单块 ESP32-S3 同时处理语音和五路舵机是可行的。CPU 和 PWM 通道数不是当前主要瓶颈，主要问题是：

- 舵机电源峰值导致 ESP32 欠压重启；
- 舵机和长线产生的电磁噪声污染麦克风；
- 阻塞式动作代码妨碍录音、网络传输或语音播放；
- 五个舵机同时启动造成机械冲击和瞬时大电流。

### 4.2 PWM 驱动两阶段策略

**原型阶段：保留 PCA9685。**

- 只占两根 I2C 信号线，便于快速扩展到五路。
- PWM 输出不依赖语音任务调度，便于先验证动作与机械结构。
- 缺点是模块尺寸偏大，并增加一块板和连接器。

**紧凑版：评估 ESP32-S3 直接输出五路 LEDC PWM。**

- 可去掉 PCA9685 模块，但仍必须保留独立舵机电源母线。
- 需要完成 GPIO 冲突审计、五路并发抖动测试以及语音播放期间的稳定性测试。
- 若直驱稳定性或布线不理想，最终方案可改为一块小型定制载板，把 PCA9685、电源分配和插座集成在一起，而不是使用成品大模块。

### 4.3 软件结构调整

五路通道建议统一命名为：

```text
front_left, front_right, rear_left, rear_right, tail
```

后续代码按以下边界调整：

- `RobotIntent`：描述开心、安慰、好奇、休息等高层意图；
- `MotionController`：把意图展开为五路关键帧；
- `ServoDriver`：只负责角度限制和 PWM 输出；
- 独立 FreeRTOS 动作任务：通过队列接收动作，按时间片更新五路舵机；
- 语音、网络回调只投递意图，不直接执行长时间 `vTaskDelay()`。

这样可以让语音播放与动作同步进行，并可记录“回复开始播放”和“动作开始”的时间差。

## 5. 供电与布线优化

### 5.1 电源原则

- 不允许五个舵机从 ESP32 开发板的 5V/3.3V 引脚取电。
- 成品状态下 ESP32 不依赖 USB 供电：2S 电池经过 5V 稳压后，5V 母线分别连接舵机支路和 ESP32 开发板的 `5V/VIN` 输入；ESP32 再由板载稳压器产生 3.3V，供麦克风和 PCA9685 的 `VCC` 使用。
- USB 只用于烧录和调试。若开发板没有确认具备 USB 5V 与外部 5V 的电源隔离，调试时应断开外部 `5V/VIN`，或使用断开 5V 线、只保留数据线的 USB 线，避免两路 5V 互相倒灌。
- 2S 锂电池、TP5100、保护板和降压模块的职责必须分别确认。
- 舵机使用独立的 5V 大电流支路，ESP32/音频使用较干净的逻辑电源支路，所有模块共地。
- 以 SG90 级舵机估算时，应按多个舵机同时启动的峰值留余量；第一版电源建议从持续 5V/5A 级别开始验证，而不是相信小模块的瞬时宣传值。
- 在舵机电源入口附近增加大容量低 ESR 电容，起始可试 `1000–2200µF`，每个模块附近保留去耦；最终数值以示波器或欠压日志验证。
- 加入总电源开关、保险丝或自恢复保险丝，并确保电池具备匹配 2S 的保护功能。

成品单电池供电拓扑：

```text
2S 7.4V 电池（满电 8.4V）
        │
   2S 保护板/BMS
        │
    保险丝＋总开关
        │
  5V/6A～8A 稳压模块
        │
        ├── 舵机支路：PCA9685 V+ → 五只舵机
        │              舵机入口并联 2200～4700µF 电容
        │
        ├── 主控支路：ESP32-S3 的 5V/VIN
        │              ESP32 板载 3.3V → INMP441、PCA9685 VCC
        │
        └── 音频支路：MAX98357A VIN（按实际模块允许电压接 5V）

所有支路 GND 在电源分配点共地。
```

这里的“一个电源”指一块电池。锂电池电压会变化，因此仍必须经过稳压；所谓 5V 充电宝内部同样包含稳压电路。若只使用一个 5V 稳压模块，应采用星形分支和滤波，避免舵机电流经过 ESP32 或麦克风的地线。

### 5.2 减小体积的优先顺序

1. 先确定五个舵机所需扭矩和实际同时动作数量。
2. 用一个满足峰值电流的紧凑同步降压/UBEC 替代体积较大的 LM2596 成品板。
3. 把舵机电源分配、公共地、滤波电容和插座集中到洞洞板或定制 PCB。
4. 验证 ESP32 直出五路 PWM，成功后再移除 PCA9685；或者把 PCA9685 芯片直接集成到小型载板。
5. 最后才根据机械实测替换更小舵机。

### 5.3 线束结构

- 面包板只用于低电流逻辑验证，不承载舵机电流。
- 使用一块中心配电板，五个舵机采用三针防呆插座；电源采用星形分配，避免串接。
- 舵机电源线优先使用比杜邦线更粗的线材；信号线与麦克风数据线分开走线。
- 电池、降压、舵机母线尽量靠近机器人重心；麦克风远离舵机、降压电感和大电流线。
- 线束按前左、前右、后左、后右、尾巴编号，并预留应力释放和可拆卸接口。
- 最终使用可拆卸电子内胆，避免清洗毛绒外套时拉扯线束。

## 6. 论文可用的量化指标

### 6.1 语音识别

| 指标 | 计算或记录方式 | 用途 |
| --- | --- | --- |
| 字错误率 CER | 编辑距离 ÷ 参考文本字数 | 衡量普通话识别准确度 |
| 整句正确率 | 完全正确句数 ÷ 总句数 | 比 CER 更容易用于汇报 |
| 唤醒成功率 | 正确唤醒次数 ÷ 有效唤醒尝试 | 衡量 WakeNet |
| 误唤醒率 | 无唤醒词时每小时误触发次数 | 衡量日常可用性 |
| 端点完整率 | 未漏开头、未截尾的录音数 ÷ 总录音数 | 衡量录音状态机 |

建议固定 30–50 条测试句，在安静/普通室内噪声、20cm/50cm 两种距离下重复测试。比较同一批录音在优化前后的结果。

### 6.2 响应速度

至少记录以下时间点，并计算中位数 P50 和较差情况 P90：

- 说话结束到录音结束；
- 上传耗时；
- ASR 耗时；
- LLM 耗时；
- TTS 耗时；
- 音频下载耗时；
- 说话结束到开始播放的端到端延迟；
- 动作开始与语音开始的同步误差。

服务端已有 ASR、LLM、TTS 和总耗时，后续需增加统一 `request_id`，并补齐 ESP32 侧录音、上传、下载、播放和动作时间戳。

### 6.3 回复亲和力与质量

使用盲测问卷比较“规则回复/原始提示词”和“优化后回复”，每项 1–5 分：

- 温暖感；
- 自然度；
- 与用户情绪的相关性；
- 是否简洁、适合语音播放；
- 是否让人感到压力或说教；
- 整体偏好。

同时记录客观辅助指标：平均回复字数、超长回复率、安全规则通过率、LLM 回退率。论文中报告均值、标准差和偏好胜率，不把少量主观反馈表述成临床效果。

### 6.4 TTS 与整机可靠性

- 合成语音可懂度：用 ASR 反识别生成语音并计算 CER。
- 主观自然度 MOS：1–5 分。
- 音色相似度：盲听 1–5 分；后续条件允许时再增加说话人嵌入余弦相似度。
- TTS 实时率 RTF：合成耗时 ÷ 音频时长。
- 端到端成功率：一次交互完整经历识别、回复、合成、下载、播放和动作的比例。
- 后端回退率、HTTP 失败率、重启/欠压次数。
- 动作重复成功率、最大电流、动作噪声和连续运行温升。

### 6.5 建议的阶段目标

以下仅作为工程目标，需用基线测试后再调整：

- 安静环境整句识别正确率 ≥90%。
- 端点完整率 ≥95%。
- 端到端成功率 ≥90%。
- 报告 P50/P90 延迟，并使优化后 P50 至少下降 20%。
- 回复温暖感和自然度平均分 ≥4/5，或相对基线盲测偏好率 ≥65%。
- 连续 30 次动作无撞限位、无 ESP32 欠压重启。

## 7. 后续工作流程与验收门槛

### 阶段 0：机械和电源事实确认

1. 称量整机、单只脚、尾巴及连杆。
2. 测量每个转轴到负载重心的距离。
3. 明确四脚是否承重、是否需要移动整机。
4. 拍摄并记录电池标签、TP5100、LM2596、PCA9685 和 SG90 实物正反面。
5. 使用单只 SG90 完成力和电流测试。

验收：形成真实尺寸、质量、力臂、扭矩和电流表；之后才决定微型舵机型号。

### 阶段 1：五舵机独立台架

1. 暂时保留 PCA9685 和独立 5V 舵机电源。
2. 把统一工程扩展为五路命名、限位和复位配置。
3. 增加单通道测试、全体复位和分组动作串口命令。
4. 先空载，再单肢加载，最后测试最多两个舵机同时动作。

验收：每路连续动作 30 次无撞限位；全系统无掉电、无异常复位；记录峰值电流。

### 阶段 2：非阻塞动作与语音同步

1. 把串行 `vTaskDelay()` 动作改为独立任务和关键帧调度。
2. 语音/触摸/服务端统一输出 `RobotIntent`。
3. 记录动作与音频开始时间，调整同步偏移。

验收：播放语音期间动作流畅，录音和网络任务不被动作长时间阻塞。

### 阶段 3：小型化与线束定型

1. 对比“直连 ESP32 五路 PWM”和“小型 PCA9685 载板”。
2. 选择满足实测峰值电流的紧凑电源方案。
3. 制作中心配电/转接板和短线束，停止用面包板承载舵机电流。
4. 在毛绒与填充物装配状态下复测噪声、卡滞、温升和麦克风干扰。

验收：形成可装入外壳的尺寸图、接线图、BOM 和实物照片。

### 阶段 4：建立语音基线与逐项优化

1. 固定测试语料、距离和噪声条件。
2. 给服务端和 ESP32 增加结构化 JSONL/CSV 调试记录。
3. 先采集基线，再逐项调整端点检测、ASR 模型、提示词和 TTS。
4. 每次只改变一个主要变量，保留配置版本号。

验收：能够给出基线与改进后的 CER、P50/P90 延迟、成功率和主观评分对比。

### 阶段 5：整机演示与论文证据

1. 完成语音回复与五舵机动作的情绪映射。
2. 做连续交互、弱网、噪声和低电量测试。
3. 保存日志、测试表、照片和视频编号。
4. 将“已实现”“实测结果”“设计目标”严格分开表述。
